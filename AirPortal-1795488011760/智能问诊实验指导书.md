# 智能问诊系统实验指导书

> 适用项目：Java Web 医院预约系统  ↩
> 实验目标：在**不改动数据库**的前提下，给已有 Spring Boot 项目接入大模型，实现"输入症状 → 返回分诊建议"的智能预问诊页面；理解版本兼容、依赖引入、配置、类/接口/页面三层协作的完整链路。  ↩
> 前置知识：Java 21、Spring Boot 基础、Thymeleaf 基础、REST 接口概念。  ↩
> 环境要求：JDK 21、Maven（或用项目自带 `mvnw`）、IntelliJ IDEA、阿里云百炼账号（有效的 API Key）。

## 实验任务总览

本实验将逐步改造成"能用的智能问诊系统"。共 8 个必做阶段 + 1 个扩展阶段：

| 阶段    | 任务                | 核心产出                              | 对应文件                       |
| ----- | ----------------- | --------------------------------- | -------------------------- |
| 一     | 修改版本号             | 项目能编译的 Boot 3 基础                  | `pom.xml`                  |
| 二     | 引入 AI 依赖          | 大模型自动装配能力                         | `pom.xml`                  |
| 三     | 配置 API Key 与模型    | 能连上百炼的配置                          | `application.properties`   |
| 四     | 添加 Service 类      | `AiConsultService`                | `AiConsultService.java`    |
| 五     | 添加 Controller 与接口 | `AiConsultController`（页面 + 2 个接口） | `AiConsultController.java` |
| 六     | 添加页面              | Thymeleaf + Vue 3 问诊页             | `ai-consult.html`          |
| 七     | 配置安全放行            | 匿名可访问的接口与页面                       | `SecurityConfig.java`      |
| 八     | 编译与验证             | 跑通的完整系统                           | ——                         |
| 九（扩展） | 升级多轮对话            | 会追问的助手                            | 3 个文件                      |

**最终调用链**（务必先记住这张图，后面每一步都在填这条链的某个环节）：

```
浏览器 /ai-consult（Thymeleaf 渲染 + Vue 交互）
   │  ① Vue 的 send() 发送 POST /api/public/ai/consult  {"symptom":"头痛发烧"}
   ▼
② AiConsultController  接收请求 + 参数校验 + Result 包装
   ▼
③ AiConsultService     拼系统提示词 + 症状，调用 ChatClient
   ▼
④ ChatModel（DashScope 自动装配）发起 API 调用 → qwen-plus
   ▼
⑤ 返回 Result<String> 纯文本 → 前端 formatAiText() 格式化成列表/高亮/免责声明 → 显示
```

## 阶段一：修改版本号（最关键的一步）

### 1.1 为什么要做

本项目最初是用 **Spring Boot 4.0.x** 生成的，而我们要接入的 **Spring AI Alibaba 1.1.2.x 只兼容 Spring Boot 3.5.x**。版本不匹配会直接导致启动失败：

```
Type org.springframework.boot.autoconfigure.web.client.RestClientAutoConfiguration not present
```

更隐蔽的是：如果只改 `<version>` 数字、不改 **artifactId**，降级不彻底，会得到另一个错：

```
错误: 找不到或无法加载主类 com.zjsru.Chap01Application
```

**原因**：Spring Boot 4 把一批 starter 改了名字（如 `starter-web` → `starter-webmvc`），改成 3.5.9 后这些新名字在 3.5 里不存在，Web 依赖没进来，主启动类自然加载不到。

### 1.2 要做什么

打开 `pom.xml`，把父版本从 `4.0.x` 改为 `3.5.9`：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.5.9</version>   
    <relativePath/>
</parent>
```

然后把 4 处 Boot 4 的 artifactId 换成 Boot 3 的名字：

| 依赖           | 改前（Boot 4，错误）                        | 改后（Boot 3，正确）                  |
| ------------ | ------------------------------------ | ------------------------------ |
| Web          | `spring-boot-starter-webmvc`         | `spring-boot-starter-web`      |
| Web 测试       | `spring-boot-starter-webmvc-test`    | `spring-boot-starter-test`     |
| Thymeleaf 测试 | `spring-boot-starter-thymeleaf-test` | 合并进 `spring-boot-starter-test` |
| Lombok       | `<scope>annotationProcessor</scope>` | `<scope>provided</scope>`      |

同时把 MyBatis 的版本从 Boot 4 配套的 `4.0.1` 降到 `3.0.5`：

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>3.0.5</version>   
</dependency>
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter-test</artifactId>
    <version>3.0.5</version>
    <scope>test</scope>
</dependency>
```

> **注意**：`java.version` 保持 `21`，不要动。  
> **注意**：改完 `pom.xml` 后 Maven 需要重新下载依赖，第一次可能较慢，耐心等。

### 1.3 怎么验证

```bash
./mvnw clean compile -DskipTests
```

看到 `BUILD SUCCESS` 即通过。若报"找不到主类"，回头检查是不是还有 `webmvc` 字样没改干净：

```bash
grep -n "webmvc\|4.0.1" pom.xml   # 应无任何输出
```

## 阶段二：引入 AI 依赖

### 2.1 学生要做什么

在 `pom.xml` 的 `<dependencies>` 里加入 Spring AI Alibaba 的依赖：

```xml
<dependency>
    <groupId>com.alibaba.cloud.ai</groupId>
    <artifactId>spring-ai-alibaba-starter-dashscope</artifactId>
    <version>1.1.2.1</version>
</dependency>
```

> 本项目的 `pom.xml` 还带了一个 `spring-ai-alibaba-agent-framework 1.1.2.0`（高级 Agent/工具调用用）。**单轮问诊用不到它**，保留不影响运行；做基础实验时可以忽略，不要因它分心。

### 2.2 为什么这样配

| 依赖                                    | 作用                                       | 必要性        |
| ------------------------------------- | ---------------------------------------- | ---------- |
| `spring-ai-alibaba-starter-dashscope` | 自动装配 `ChatModel` Bean、DashScope 客户端、重试机制 | **必需**     |
| `spring-ai-alibaba-agent-framework`   | ReactAgent、工具调用                          | 单轮不需要，扩展才用 |

**版本兼容对照（务必记住）**：

```
Spring Boot 3.5.x  ↔  Spring AI Alibaba 1.1.2.x  ↔  Spring AI 1.1.2
```

三者是配套的。升到 Boot 4 或换成旧版 Spring AI，都会出现类缺失 / Bean 不注入的报错。

### 2.3 引入了什么能力

引入 starter 后，Spring 会自动帮我们创建一个 `ChatModel` Bean（底层就是 DashScope 的通义千问客户端）。**我们不用手写 API Key 读取、不用写 HTTP 客户端**——阶段四里直接 `@Autowired` 注入即可。这就是 starter 的价值。

验证依赖是否进来：

```bash
./mvnw dependency:tree | grep -i "spring-ai"
```

## 阶段三：配置 API Key 与模型

### 3.1 要做什么

在 `src/main/resources/application.properties` 末尾加入：

```properties
# 注意：改完系统环境变量后必须重启 IDEA，否则 IDEA 进程读的是启动时的旧环境快照。
spring.ai.dashscope.api-key=${DASH_SCOPE_API_KEY}
# 指定对话模型（qwen-turbo 已于 2026-10-10 下线，改用仍在服役的 qwen-plus）
spring.ai.dashscope.chat.options.model=qwen-plus
```

然后在**操作系统**里设置环境变量 `DASH_SCOPE_API_KEY`，值为你的百炼 API Key（`sk-` 开头）。

### 3.2 三个必踩的坑（重点讲）

**坑 1：属性前缀写错**

最常见的错误写法是 `spring.ai.alibaba.dashscope.api-key`——**这是错的**，正确的前缀是 `spring.ai.dashscope`。写错后启动会报：

```
DashScope API key must be set. Use spring.ai.dashscope.api-key
```

报错信息本身就给出了正确答案，照着改即可。

**坑 2：环境变量名必须完全一致**

配置里是 `${DASH_SCOPE_API_KEY}`（**带下划线**），你设的环境变量也必须叫 `DASH_SCOPE_API_KEY`。网上教程常用 `DASHSCOPE_API_KEY`（无下划线），照抄就读不到。

**坑 3：改完环境变量必须完全重启 IDEA**

这是最隐蔽的一个。IDEA 进程只在**启动那一刻**读取系统环境变量快照。你改完系统环境变量后，IDEA 里跑的 Spring Boot 进程读到的还是旧值（或空值），请求发出去了但被百炼拒绝：

```
HTTP 401 - {"code":"InvalidApiKey","message":"Invalid API-key provided."}
```

**正确做法**：`File → Exit` 完全退出 IDEA（不是关窗口），再重新打开项目并 Run。

> **401 排查口诀**：先直接用 `curl` 拿你手上的 Key 打一次百炼官方 API，确认 Key 本身有效；再查配置来源（环境变量 / 配置文件 / IDEA Run Configuration）。Key 有效但项目 401，几乎都是"环境变量没被读到"，而不是 Key 错了。

### 3.3 关于模型名

| 模型           | 状态    | 说明                                               |
| ------------ | ----- | ------------------------------------------------ |
| `qwen-plus`  | ✅ 在用  | Spring AI Alibaba 1.1.2.1 的**框架默认值**，本项目显式写出便于教学 |
| `qwen-turbo` | ❌ 已下线 | 百炼于 2026-10-10 下线，调用会报"模型不存在/无权限"                |

其实不写 `spring.ai.dashscope.chat.options.model` 这一行，框架默认就是 `qwen-plus`。写出来是为了让学生看清"模型在哪里配置、怎么换"。

> **事实核验提示**：百炼模型迭代很快，若想换其他模型（如 qwen3 系列），先到阿里云百炼控制台的"模型广场"确认模型编码当前在售、账号有权限，再改这一行；不要照抄旧教程里的模型名。

## 阶段四：添加 Service 类（业务层）

### 4.1 要做什么

新建 `src/main/java/com/zjsru/service/AiConsultService.java`，完整代码如下：

```java
package com.zjsru.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.stereotype.Service;

@Service
public class AiConsultService {
    /** 系统提示词：约束 AI 的身份与回答边界（医疗场景必须谨慎）。 */
    private static final String SYSTEM_PROMPT = """
            你是一名医院的智能预问诊助手。请遵守：
            1. 只做初步分诊建议，不做确诊、不开处方、不给用药剂量。
            2. 根据患者描述的症状，建议可能的就诊科室，并给出 1-3 条就医前的注意事项。
            3. 若出现胸痛、呼吸困难、意识不清、大出血等急症信号，明确提示立即急诊就医。
            4. 回答用中文、简洁分录，末尾附一句免责声明：本建议仅供参考，不能替代医生诊断。
            """;

    private final ChatClient chatClient;

    /** 构造时把模型包装成 ChatClient，后续每轮调用只关心 system + user。 */
    public AiConsultService(ChatModel chatModel) {
        this.chatClient = ChatClient.create(chatModel);
    }

    /**
     * 对一段症状描述给出分诊建议。
     * @param symptom 患者自述的症状
     * @return 模型返回的文本建议
     */
    public String consult(String symptom) {
        return chatClient.prompt()
                .system(SYSTEM_PROMPT)   // 告诉 AI 身份与边界
                .user(symptom)           // 患者自述的症状
                .call()                  // 调用模型
                .content();              // 取回文本回答
    }
}
```

### 4.2 逐行理解

| 代码                                  | 作用               | 为什么                  |
| ----------------------------------- | ---------------- | -------------------- |
| `@Service`                          | 交给 Spring 管理     | Controller 才能注入它     |
| 构造器注入 `ChatModel`                   | 拿到框架自动装配的模型 Bean | 不用自己读 Key、写 HTTP 客户端 |
| `ChatClient.create(chatModel)`      | 把模型包装成好用的客户端     | 用链式 API 拼提示词         |
| `SYSTEM_PROMPT`（文本块 `"""`）          | 约束回答边界           | 医疗场景必须防误诊、防开药        |
| `.system().user().call().content()` | 一次完整调用           | 四步固定套路               |

> **医疗合规提醒**：系统提示词第 1、3、4 条不能删——"不确诊、不开药、急症提示急诊、免责声明"是医疗类 AI 应用的底线约束。删了它，模型可能给出危险的诊断性回答。

## 阶段五：添加 Controller 与接口（控制层）

### 5.1 要做什么

新建 `src/main/java/com/zjsru/controller/AiConsultController.java`：

```java
package com.zjsru.controller;

import com.zjsru.service.AiConsultService;
import com.zjsru.util.Result;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;

@Controller   // 类上不是 @RestController，页面方法才会走视图解析
public class AiConsultController {

    private final AiConsultService aiConsultService;

    public AiConsultController(AiConsultService aiConsultService) {
        this.aiConsultService = aiConsultService;
    }

    @GetMapping("/ai-consult")                 // 打开问诊页面
    public String page(Model model) {
        model.addAttribute("pageTitle", "智能预问诊助手");
        model.addAttribute("tip", "输入症状描述，例如：最近三天头痛、发烧 38.5℃，该看什么科？");
        model.addAttribute("apiUrl", "/api/public/ai/consult");  // 传给前端，不用写死
        model.addAttribute("emptyTip", "还没有对话，请在下方输入症状开始咨询……");
        return "ai-consult";                   // 返回视图名，不是 JSON
    }

    public record ConsultRequest(String symptom) {}

    @PostMapping("/api/public/ai/consult")      // 页面 fetch 用这个
    @ResponseBody                               // 少了它，返回值会被当视图名解析
    public Result<String> consult(@RequestBody ConsultRequest request) {
        return doConsult(request.symptom());
    }

    @GetMapping("/api/public/ai/consult")       // 课堂演示：地址栏直接打开
    @ResponseBody
    public Result<String> consultGet(@RequestParam String symptom) {
        return doConsult(symptom);
    }

    private Result<String> doConsult(String symptom) {   // 共用逻辑：校验 → 调用 → 包装
        if (symptom == null || symptom.isBlank()) return Result.fail("症状描述不能为空");
        return Result.success(aiConsultService.consult(symptom));
    }
}
```

`Result` 工具类项目里已有（`com.zjsru.util.Result`），提供 `success(data)` 和 `fail(msg)` 静态方法，无需新建。

### 5.2 三个必须讲清的注解陷阱

**陷阱 1：`@Controller` 还是 `@RestController`？**

本类**同时**要返回 HTML 页面和 JSON 接口，所以用 `@Controller`：

- 页面方法 `page()` 返回字符串 `"ai-consult"` → 视图解析器找到模板并渲染；
- 接口方法**必须单独加 `@ResponseBody`** → 才返回 JSON。

如果图省事写成 `@RestController`，类上的 `@ResponseBody` 会让页面方法把字符串 `"ai-consult"` 直接吐给浏览器，看到的就是一行纯文本 `ai-consult`，而不是页面。

**陷阱 2：接口方法漏了 `@ResponseBody`**

现象很诡异：接口返回**空**，日志里报：

```
Error resolving template [api/public/ai/consult]
```

原因是 `Result<String>` 被当成了视图名去找模板。给接口方法补上 `@ResponseBody` 即可。

**陷阱 3：为什么页面路径和接口路径前缀不同**

页面是 `/ai-consult`，接口是 `/api/public/ai/consult`。**不要在类上加 `@RequestMapping("/api/public/ai")`**——那样页面路径也会被加上前缀，两个 URL 就对不上了。路径全部写在方法上。

### 5.3 为什么接口放 `/api/public/**` 下

`/api/public/` 这个前缀在安全配置里被显式放行（见阶段七）。放在它下面，**匿名用户也能调用问诊接口**——这正是我们要的（问诊页不需要登录）。

### 5.4 忘记注入 Service 的报错

如果写了 `aiConsultService.consult(...)` 却没有字段和构造器，编译会报"找不到符号 aiConsultService"。**构造器注入是必须的步骤**，不要漏。

## 阶段六：添加 Thymeleaf + Vue 页面（展示层）

### 6.1 学生要做什么

新建 `src/main/resources/templates/ai-consult.html`。页面较长，分三块理解。

**第一块：Thymeleaf 骨架 + Vue 挂载点**

```html
<html lang="zh-CN" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title th:text="${pageTitle}">智能预问诊助手</title>
    <style> /* 样式略，见完整文件 */ </style>
</head>
<body>
<div id="app" class="wrap" v-cloak>
    <h1 th:text="${pageTitle}">智能预问诊助手</h1>
    <div class="tip" th:text="${tip}">输入症状描述</div>

    <div id="msgs" ref="msgs">
        <div v-if="messages.length === 0" class="empty">{{ emptyTip }}</div>
        <div v-for="(m, i) in messages" :key="i" class="msg" :class="{ ai: m.who === 'ai' }">
            <b>{{ m.who === 'me' ? '我' : 'AI 预问诊助手' }}</b>
            <div class="bubble" v-html="m.html"></div>
        </div>
    </div>

    <div class="bar">
        <textarea v-model="symptom" @keydown.enter.exact.prevent="send"
                  placeholder="请描述您的症状……"></textarea>
        <button @click="send" :disabled="loading || !symptom.trim()">
            {{ loading ? '思考中…' : '发送' }}
        </button>
    </div>
</div>
```

- `th:text="${pageTitle}"`：Thymeleaf 服务端渲染，把 Controller 传来的标题填进去；
- `v-cloak`：Vue 初始化前隐藏元素，防止看到 `{{ }}` 闪烁；
- `v-model`、`v-for`、`v-if`、`@click`：Vue 接管交互。

**第二块：Vue 引入与接口地址注入**

```html
<!-- Vue 3 走 CDN 引入：避免改动后端 SecurityConfig 去放行本地静态 js -->
<script src="https://cdn.jsdelivr.net/npm/vue@3/dist/vue.global.prod.js"></script>
<script th:inline="javascript">
/*<![CDATA[*/
if (typeof Vue === 'undefined') {
    document.getElementById('app').outerHTML =
        '<div class="load-fail">Vue 加载失败，请检查网络后刷新页面。</div>';
} else {
    // Thymeleaf 把服务端变量注入到 JS，接口地址不用写死
    const API_URL = /*[[${apiUrl}]]*/ '/api/public/ai/consult';
    const { createApp } = Vue;

    createApp({
        data() {
            return { symptom: '', messages: [], loading: false };
        },
        methods: { /* 见第三块 */ },
        updated() {
            const box = this.$refs.msgs;
            if (box) box.scrollTop = box.scrollHeight;   // 自动滚到底部
        }
    }).mount('#app');
}
/*]]>*/
</script>
```

> **为什么 Vue 用 CDN，不下载到本地 `static/`？**
> `SecurityConfig` 里非放行路径需要登录，把 `vue.js` 放进 `static/` 会增加放行配置的工作量。用 CDN 引入最省事，且页面对 CDN 失败有明确提示（不会白屏）。**代价：演示时需要联网。**

**第三块：`send()` 发请求 + `formatAiText()` 格式化**

```js
// 单轮：只发症状，不带历史
async send() {
    const symptom = this.symptom.trim();
    if (!symptom || this.loading) return;

    this.messages.push({ who: 'me', html: this.escapeHtml(symptom) });
    this.symptom = '';
    this.loading = true;

    try {
        const resp = await fetch(API_URL, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ symptom: symptom })   // 单轮只发 symptom
        });
        const json = await resp.json();
        if (json.code === 200) {
            this.messages.push({ who: 'ai', html: this.formatAiText(json.data) });
        } else {
            this.messages.push({ who: 'ai', html: this.escapeHtml('出错了：' + json.msg) });
        }
    } catch (e) {
        this.messages.push({ who: 'ai', html: this.escapeHtml('请求失败：' + e.message) });
    } finally {
        this.loading = false;
    }
}
```

`formatAiText()` 做四件事（完整实现见项目文件）：

1. 拆出末尾"仅供参考/不能替代医生诊断" → 灰色小字免责声明；
2. 按行拆，`-` / `•` / `1.` 开头 → `<ul><li>` 列表；
3. "急诊/立即就医" → 红色高亮，科室名 → 绿色高亮；
4. **所有文本先 `escapeHtml()` 转义**再拼 HTML。

> **为什么必须转义**：AI 返回的是不可信文本，直接 `v-html` 插入有 XSS 风险。先转义、再对白名单内容做高亮，是前端铁律。

### 6.2 三层职责分工（核心教学思想）

| 层    | 技术        | 负责                               |
| ---- | --------- | -------------------------------- |
| 骨架渲染 | Thymeleaf | 渲染标题、提示语，`th:inline` 注入接口地址      |
| 交互   | Vue 3     | `v-model` 取值、`v-for` 渲染、发请求、自动滚屏 |
| 格式化  | Vue 方法    | 把纯文本变成列表/高亮/免责声明                 |

**一句话**：后端只管给数据（纯文本），展示效果由前端决定——改样式不用动后端一行代码。

## 阶段七：配置安全放行

### 7.1 学生要做什么

在 `src/main/java/com/zjsru/config/SecurityConfig.java` 的 `requestMatchers(...)` 里加入两个路径：

```java
.requestMatchers("/", "/ai-consult", "/api/public/**", "/login",
                 "/static/**", "/css/**", "/js/**", "/images/**", "/logout").permitAll()
```

关键是 `/ai-consult`（问诊页面）和 `/api/public/**`（问诊接口）。

### 7.2 为什么

项目用了 Spring Security，默认所有请求要登录。问诊页和接口是给匿名患者用的，必须显式放行。若漏配，页面会 **302 跳转到登录页**，或接口被拦截导致前端拿到 HTML 而不是 JSON（表现为 `Unexpected end of JSON input`）。

> **注意**：本项目当前 `anyRequest().permitAll()`，其实不配也能访问；但显式写出 `/api/public/**` 是规范做法——将来若改成 `authenticated()`，问诊接口仍能正常匿名访问。

## 阶段九（扩展）：升级为多轮对话

单轮版的局限：模型不知道你上一轮说了什么——第二句"三天了"它不知道"三天"指的是什么症状。要让 AI **根据病人。

下面给出改动要点。

### 9.1 核心原理（课堂重点）

**模型没有记忆**。所谓"多轮对话"，本质是**每一轮都把之前的全部问答重新发给模型**。所以要做两件事：

1. 请求体带上历史；
2. 系统提示词改成"先追问、后建议"。

### 9.2 三种历史传递机制怎么选

| 方案                    | 做法                    | 评价                  |
| --------------------- | --------------------- | ------------------- |
| **A. 前端传历史（推荐）**      | Vue 把成功问答打包进请求体，后端无状态 | 改动最小、刷新即新会话、学生能看清原理 |
| B. 后端 Session         | `HttpSession` 存对话     | 要加清空接口、重启丢、多标签页串会话  |
| C. ChatMemory Advisor | Spring AI 的记忆组件       | 代码少但对教学是黑盒          |

**选 A**：后端保持无状态，历史由前端携带。

### 9.3 改动清单（3 个文件）

| 文件                         | 改动                                                                        |
| -------------------------- | ------------------------------------------------------------------------- |
| `AiConsultService.java`    | 提示词改两阶段；新增 `consult(symptom, history)`，用 `messages(List<Message>)` 构造完整对话 |
| `AiConsultController.java` | `ConsultRequest` 增加 `history` 字段并透传                                       |
| `ai-consult.html`          | 消息对象加原文 `text` 和 `ok` 标记；新增 `buildHistory()`；加"新咨询"按钮                     |

### 9.4 会追问的系统提示词（灵魂）

```
你是医院智能预问诊助手，采用"先追问、后建议"策略：
1. 首轮不要给科室建议，先针对患者描述挑出最关键的 1-2 个缺失信息提问
   （年龄、持续时间、具体部位、伴随症状、有无基础病等）。
2. 每次只问 1-2 个问题，简短中文，不要一次列一大串。
3. 追问最多 3 轮；信息够了就给 1-3 个科室 + 就医前注意事项。
4. 出现胸痛、呼吸困难、意识不清、大出血等急症信号，立即提示急诊，停止追问。
5. 不确诊、不开药、不给剂量；末尾附：本建议仅供参考，不能替代医生诊断。
```

> **第 3 条的"最多 3 轮"必须写**。不写轮次上限，模型会无限追问下去，患者永远得不到结论——这是多轮问诊最常见的坑。

### 9.5 两个易错点

1. **历史必须在追加本轮消息之前构造**。否则本轮症状会被发两遍（既在 history 里、又在 symptom 里）。
2. **失败轮次不能进历史**。只把 `ok: true` 的消息放进 history，否则模型会学着说"请求失败"。

### 9.6 多轮验证

```bash
# 第一轮：空历史 → 期望"追问"而不是直接给科室
curl -X POST http://localhost/api/public/ai/consult \
  -H "Content-Type: application/json" \
  -d '{"symptom":"我最近头痛","history":[]}'

# 第二轮：带历史 → 期望结合上下文，不重复问过的问题
curl -X POST http://localhost/api/public/ai/consult \
  -H "Content-Type: application/json" \
  -d '{"symptom":"三天了，还有点发烧","history":[{"role":"user","content":"我最近头痛"},{"role":"assistant","content":"请问头痛持续多久了？哪个部位？"}]}'
```
